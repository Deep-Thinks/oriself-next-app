# Probe 反馈结构化 issue list

> 范围：oriself 项目截至 2026-05-27 的全部 10 条反馈（v1 ×5 ＋ v2.6.1 ×5）。
> 目的：把零散吐槽聚合成可决策的 issue 列表，标注证据 / 严重度 / 版本归属 /
> 当前修复状态，作为下一步改进方案的输入。

## 0. 阅读约定

- **严重度**：根据 [出现频次 × 是否导致关页 × tester 关页时点] 综合定 P0/P1/P2。
  - **P0** = 不修就直接关页 / 拿到错误结果（伪信号）
  - **P1** = 体验性不爽，会拉低 NPS 但能走完
  - **P2** = 锦上添花
- **状态**：
  - `fixed`     = v2.6.1 已部署且后续反馈不再出现
  - `partial`   = v2.6.1 改了但 v2.6.1 用户仍有相关吐槽
  - `open-v2.6.1` = v2.6.1 新出现 / 未触达
  - `open-v1`   = v1 提过、v2.6.1 没动也没新证据（信号弱）
- **证据格式**：`#<feedback_id>` 引用 Probe 平台条目（见附录原文）

## 2. 单 issue 详情

### I-1 · 流程长度不可见

- **用户怎么说**
  - v1 #7：「不知道还要多久结束，没有进度条」
  - v1 #14：「全流程太漫长，13 回合就想关」「15 回合时加总结按钮」
  - v2.6.1 #19：「问了两三轮不知道什么时候结束」
- **当前状态**：partial
  - `980ccf1 fix/web-enter-and-converge-button` 第 6 轮起暴露「现在收信」按钮 → 解决了"能不能现在就结束"
  - 但「**还剩多少轮**」「**走到第几步**」依然没有视觉化
- **为什么是 P0**：tester 在中途关页就是 funnel 顶端漏水，比报告质量差更致命

### I-2 · 同一件事死磕

- **用户怎么说**
  - v1 #10：「他一直抓着我的回答往下延伸，希望聊别的话题」
  - v2.6.1 #18：「生成的回复都围绕着我说的那件事一直追问，后面追问已经无意义」
- **当前状态**：partial
  - `1d0d834 v2.6.1 · skill 反射倾听限制` 是从同一个事故面切进去的（限制单事件追问轮数）
  - 但 v2.6.1 用户 #18 给的证据说明：限制不够强 / 没切换到新话题领域
- **为什么是 P0**：reflective listening 失控会触发 I-3（信号面太窄→画像错）

### I-3 · MBTI 识别错位

- **用户怎么说**
  - v1 #6：「我测试人格是 enfp，他给我的结果是 istj，完全相反」（聊《蛊真人》小说）
  - v2.6.1 #15：「他似乎一直对我有一个人格预设，但是这个预设和我不相符，后面的启发式提问对我来说莫名其妙」
  - v2.6.1 #16：「总结多半是根据我说的内容来总结的」（暗示泛化能力差）
- **当前状态**：partial
  - `b21a001 feat/roleplay-detection` 已对角色扮演 / 架空世界识别 + 提 N 信号注意力
  - `0a2d9da feat/server-confidence-meta-extractor` 入库 confidence_json + 矛盾检测
  - 但 #15 是 5-21 当天提交的反馈，距 b21a001 合并不到一天，可能还没在 prompt 上体现充分；且 b21a001 只覆盖了"聊小说"这一种偏差源，**早期问句导致的过早 anchoring** 还没动
- **为什么是 P0**：识别错 = 产品价值归零，比 I-4/I-5/I-6 全部加起来都严重

### I-4 · "开始收信"按钮意图不明 + 无 loading

- **用户怎么说**
  - v2.6.1 #16：「'开始收信'出现时也没明白他到底是想干什么，犹豫过要不要点 / 点完后过一会儿才出窗口，以为系统出问题了 / 发送到我微信了 / 加一个'等待生成中'提示」
- **当前状态**：open-v2.6.1
- **触发面**：按钮出现的瞬间（第 6 轮起）+ 点击后到 issue 报告 ready 的间隔

### I-5 · 出报告后不自动下滑

- **用户怎么说**
  - v2.6.1 #15：「下拉页面才能看到结果，不能自动下滑」「Q5: 先把出答案后查看答案的自动下拉做出来」
- **当前状态**：open-v2.6.1
- **触发面**：报告生成完毕的瞬间

### I-6 · 聊天页视觉

- **用户怎么说**
  - v2.6.1 #19：「聊天的页面有很多线条，字体也很细，看起来有点不太舒服」
  - v2.6.1 #21：「聊天界面聊天框不是很明显，以为是提示词」「字体很细，和很多线条看起来很像」
- **当前状态**：open-v2.6.1
- **判断**：两条反馈来自不同 tester（21 还被 AI 标 `semantic_duplicate`，但 ID 不一致），信号叠加

### I-7 · 首页对话框位置不显眼

- **用户怎么说**
  - v2.6.1 #18：「第一页看到页面会集中在中间，思考是让我直接从三条里选一个吗？才看到了最下面的对话框」
  - v2.6.1 #21：「我第一眼最想点聊天框，犹豫是因为聊天框不是很明显」
- **当前状态**：open-v2.6.1
- **根因**：三条预设候选放在中间，输入框压在底，视觉权重反了

### I-8 · 缺情绪共情

- **用户怎么说**
  - v2.6.1 #16：「我说完以后他给的安慰或者说分析有些没那么打动我的内心，受到的反馈不够 / 添加一些情绪反馈，而不是只分析一句话就开始继续问问题」
- **当前状态**：open-v2.6.1
- **判断**：和 oriself "信件 / 温柔回望" 的产品定位强相关；只有一条证据但击中产品命门

### I-9 · 报告没建议 + 配色丧失阅读欲

- **用户怎么说**
  - v1 #5：「希望最后的分析里面加一些建议部分。是那种实际的建议」
  - v2.6.1 #16：「最终总结页面的配色也有点让人丧失阅读欲望」
- **当前状态**：open-v1（建议） + open-v2.6.1（视觉）
- **触发面**：issue HTML 报告

### I-10 · 大题目无从答起

- **用户怎么说**
  - v1 #14：「他会问我'我期待什么'，这个就让我不好回答，题目选取太大」
- **状态**：open-v1
- **判断**：和 I-2 是一个根因的两面 —— skill 抽象提问 vs 具象提问的平衡

### I-11 · 进入期望错位

- **用户怎么说**
  - v1 #6：「我以为能生成我的长相」 / v1 #14：「oriself 这个名字不太直观，第一想法是新奇模式的 mbti 测试题」
  - v2.6.1 #19：「以为是用来占卜的」 / v2.6.1 #21：「我以为他是用来占卜的」
- **状态**：open-v1（重复反复）
- **判断**：landing 的"是什么 / 做什么 / 不做什么" 文案空白

### I-12 · 选项化提问的缺失

- **用户怎么说**
  - v2.6.1 #15：「我其实更期待有 4 个选项这种形式，D 选项是其他（用于用户自己输入想法），不然容易走神或者一下子想不到答案」
- **状态**：open-v2.6.1
- **判断**：这是 tester 的"我以为是 MBTI 测试"心智模型映射到产品上的诉求，**取舍点**——
  oriself 的产品立场恰恰是"不要让用户选选项，要让用户讲"，但可作为"低能量时的快通道"备选

## 3. 按"修复成本 × 影响"四象限

```
影响 ↑
高  | I-3 识别错位       | I-1 流程感
    | I-2 死磕           | I-4 按钮 loading
    |                    | I-8 情绪共情
----+--------------------+--------------------→ 成本
低  | I-11 landing 文案  | I-5 自动下滑
    | I-7 首页对话框     | I-6 视觉细线
    | I-9 报告配色       | I-10/I-12 提问形态
```

- **左上 = 优先做**（影响大但成本低）：I-7、I-11 文案/布局调整
- **右上 = 战略级**：I-1、I-2、I-3、I-4、I-8 全是 skill / 后端协议级改造
- **左下 = 顺手做**：I-5、I-6、I-9 视觉/前端
- **右下 = 慎重做**：I-10、I-12 产品立场抉择

## 4. 数据局限性声明

- **样本量小**：10 条反馈，v2.6.1 只 5 条，单条吐槽就能拉升表面频次。
- **AI 标注未必准**：#21 标了 `semantic_duplicate`，但 #19 / #21 两位 tester 独立提到细字体和线条，应当合并而非剔除。
- **来源单一**：全部走 Probe 公开大厅，没有定向渠道反馈作为对照。
- **缺转化率数据**：funnel "进入→第 1 轮→第 6 轮→收信→看完报告" 的具体掉率没记录，I-1 / I-4 / I-5 谁更致命无法量化。

> 行动建议：本 list 是定性输入，**不要直接拿来做 KPI**。改进优先级最终落在
> 「这一条命中产品命门吗」而不是「几个人说了」。
